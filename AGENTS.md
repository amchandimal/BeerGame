# Project handover

Classroom Challenge additionally supports up to 32 same-role competitors, with host-authoritative independent engines and a shared seeded scenario in `src/app/challenge.ts`. Rankings are lowest own cost first, elapsed milliseconds breaking ties. Six-digit numeric room codes replace long codes; joins no longer require names. Nicknames are required before start. Classroom guests leaving do not block other runs; the creator must remain connected. Preserve full MCP weeklyCosts/leaderboard fields and scoped operational data. `challenge.spec.ts` covers scenario fairness, cost reconciliation and ranking; real MCP integration includes five classroom participants and live results after host completion.

Describe the request, implementation, validation and any limitations in each pull request.

The application has single-player and WebRTC multiplayer modes for 1–4 humans, with system players filling unassigned roles. Human roles are set at game start, and turns wait only for human roles the system is not playing. In a started Team game a guest who leaves, or stays disconnected for 60 seconds, keeps their seat and save; an in-game message asks the creator (or any connected player while the creator is offline, first answer counts) whether the system plays the role. The server records decisions (room automated/waiting/takeBack); the host applies them, keeps any order already sent, and hands a role back to a returning player only after its next week advance has been checkpointed. Classroom leaving is unchanged. `src/app/game.ts` is the deterministic engine. `server/index.mjs` handles signaling, lobby membership and role reservations, and serves production builds. Game orders/snapshots travel through WebRTC data channels in `src/app/multiplayer.ts`, not through the signaling server.

Build with `npm run build`, then validate with `npm test`. The signaling integration test currently verifies the built app's HTTP response, so build first. `npm start` runs the Angular dev server and signaling server together. `npm run serve` serves the production build at localhost:8787. Preserve the one-play-per-week animations, lead-time semantics and signed metric comparisons when extending the game.

`mcp/index.mjs` is the local stdio AI-player server. `mcp/sessions.mjs` owns isolated Playwright browser contexts; `src/app/game-agent.ts` exposes validated commands only on opt-in `#agent` pages. Preserve browser-native WebRTC gameplay and expected-week/duplicate checks. `npm run test:mcp` runs the real stdio/browser/RTC integration suite against an ephemeral app server; set `BEER_GAME_BROWSER_CHANNEL=msedge` on this machine, or install Chromium with `npm run mcp:install-browser`. Client setup and limitations are documented in `mcp/README.md`.

Information visibility is defined in `src/app/visibility.ts`: network (default), dyadic (own + immediate neighbors), none (own only). Preserve per-recipient WebRTC projections and identical UI/MCP/history/CSV scope. Guest BeerGame models use internal placeholders for undisclosed party positions; never expose those as actual data or execute the engine on a guest. Host authority retains the complete engine but player-facing projections still apply. Room topology and submitted-role status are public; hidden amounts, team total and out-of-scope customer demand must not leak before the reveal. Hidden information is revealed once the game is over (owner decision, UX-16): single-player and Team when week 24 completes; Classroom only when every run is over (all finished, or the creator's Finish classroom marked the rest incomplete), so a finished student cannot pass on demand to classmates still playing. `dataScope(level, revealed)` is the single switch for the UI, MCP, history and CSV; `MultiplayerSession.revealed`/`over` say when. The host then sends one unfiltered snapshot (`revealed: true`); in Classroom each competitor receives only their own run, never another student's. Revealed values are labelled "Revealed after the game" (banner or chip, board stations, Game stats cards, debrief); MCP state has `revealed` and `revealedRoles`. The completion-screen debrief and MCP `state.debrief` share `src/app/debrief.ts` (bullwhip chart data, order swing = order SD ÷ customer-demand SD, peak backlog, holding/backlog cost split that reconciles exactly with engine costs, CSV filename with room or scenario, role and date); it appears only once the whole chain is visible. Tests include `visibility.spec.ts`, `debrief.spec.ts`, all three policies in the real MCP integration suite, and the reveal test in `mcp/resume.integration.spec.mjs`.

TURN relay: `/rtc-config` carries STUN (and a self-hoster's static TURN_URLS) only. With CLOUDFLARE_TURN_KEY_ID and CLOUDFLARE_TURN_KEY_API_TOKEN, `issueNeeded` in server/index.mjs runs whenever a member comes online (create, join, resume) and requests short-lived credentials (`issueIce`, `cloudflareIce`, TURN_TTL_SECONDS default 10800, 3-second timeout, port 53 removed) only for members with an online counterpart (the host: any guest; a guest: the host), never for a member alone, at most once per connection and 120 a minute. It holds that socket's messages so `{type:'ice'}` arrives before whatever creates peers (a guest's session, the host's room listing its first online guest, signals); the client merges it into `config` (`withTurn`), and a peer created before it that fails restarts ICE with it (`restartIce`). `client.turn` keeps the usernames in memory only, for `revoke` (`revokeCloudflareIce`: one attempt, 3 s, failures only warn; it clears them, so nothing is revoked twice) on a plain disconnect of the member's current socket (an old socket a resume replaced revokes nothing), leave, removal (also Start without), reservation expiry, the host ending the room, resume replacement, and `revealGraceMs` (30 s) after the host's `finished` (at once if they disconnect first); the host's own goes when the finished room expires or the host leaves or disconnects, since late players reconnect to it. After the reveal the client no longer reports failed peers, because revocation drops relays. Failure means STUN only and one warning. Never log or persist credentials or the token, and keep static TURN and Cloudflare mutually exclusive (start-up refuses both). `scripts/check-turn.mjs` checks the key and revocation.
