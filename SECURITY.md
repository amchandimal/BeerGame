# Security

Do not post live room codes, personal data or exploit details in public issues. Report security problems privately to skillidaus@gmail.com with steps to reproduce. This contact is also used in site.config.json.

Rooms are invite-code based, not authenticated accounts. Creators are trusted authorities, and visibility is a learning mechanic rather than protection against a malicious creator. Codes are not appropriate for confidential sessions. The host must remain connected; state is not persistent. The server limits message size/rate and total connections, but these are not DDoS protection. Apply infrastructure rate limits and monitoring before a broadly advertised service.

Production checks browser Origin against PUBLIC_ORIGIN. WebRTC requires HTTPS. The hosted beergame.io beta relays connections that cannot be made directly through Cloudflare's TURN service. Its credentials are short-lived (3 hours by default) and issued per player, only to a room member who has someone online to connect to, never to a player alone in a room; `/rtc-config` never contains them, and the Cloudflare API token stays on the server. The server revokes each credential once it is no longer needed: when the player disconnects, leaves or is removed, their reservation expires, the room closes, a resume replaces it, or the results are revealed. Revocation is best effort (one attempt; a failure leaves the credential to expire). Issuance is capped server-wide (120 a minute) and at one per connection. A member can still read their own credentials and use them for as long as their connection stays open, up to the lifetime; the relay forwards to any destination and is billed by traffic, so set a Cloudflare budget alert and monitor usage. To stop the relay, unset the Cloudflare variables and restart the app, then delete or regenerate the TURN key in Cloudflare (see docs/DEPLOYMENT.md). Self-hosted deployments with static `TURN_URLS` should know that `/rtc-config` returns those credentials to every browser; use short-lived/scoped credentials and rotate them. Do not expose the local stdio MCP server as a public service. Restrict .env, private keys and Docker access. Review dependencies and image updates for each release.
